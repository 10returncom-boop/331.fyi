# 內容撰寫規範 CONTENT-SPEC（子代理務必嚴格遵循）

本文件是「世上最強鋼筆百科」內容檔的**唯一格式標準**。所有文章內容檔（.md）必須符合本規範，
且通過 `python build.py --check` 檢查後才算完成。

## 1. 檔案位置與命名

- 內容檔一律放在 `data/articles/<章節id>/<子分類id>/<slug>.md`
- 章節 id 與子分類 id 請查閱 `data/site.json`（16 章對照表）
- slug 必須與 `data/site.json` 的 `articles` 清單一致，**不可自創**
- 一個 slug 一篇檔案；不要新增清單外的文章

## 2. Frontmatter（檔案開頭的 `---` 區塊）

每個欄位必填，格式為 `key: 值`（每行一欄，值內不要用冒號+空格以外的結構）：

```
---
title: 文章中文標題
en: 英文名稱（供 A–Z 字母索引分組，請以英文字母開頭）
chapter: 章節id
sub: 子分類id
slug: 文章slug（與 site.json 一致）
summary: 一句話摘要（40–80 字，會成為 meta description 與卡片文字，不可含換行）
tags: 標籤1, 標籤2, 標籤3, 標籤4 （3–6 個，逗號分隔）
difficulty: 初階 / 中階 / 進階 （三選一）
updated: 2026-10-06
related: slug1, slug2, slug3 （3–5 個，必須存在於 site.json 的 articles 清單，逗號分隔）
---
```

## 3. 正文語法（輕量 markdown）

- 第一行寫 `# 標題`（會自動忽略，僅作為檔內標記）
- `## 小節標題` → 章節標題（同時進入 TOC 與右欄目錄，**建議 6–10 個小節**）
- `### 次標題` → 次級標題（可選）
- 一般段落：連續文字行，段落之間空一行
- 清單：`- 項目` 無序；`1. 項目` 有序
- 表格：連續 `| 欄A | 欄B |` 行，第二列用 `| --- | --- |` 當表頭分隔
- Callout：`> 提示：……`、`> 注意：……`、`> 小知識：……`（關鍵字決定樣式）
- 強調：`**粗體**`、`*斜體*`
- FAQ：小節標題用 `## 常見問題`（或 `## 常見問題 FAQ`），其後每組問答寫成
  `Q：問題` 與 `A：答案`（A 可跨多行；建議 3–5 組）

## 4. 內容品質門檻（硬性）

- 正文為**真實可讀的繁體中文專業內容**，禁止「內容規劃中」「待補」「TODO」等佔位文字
- 正文（不含 frontmatter）**至少 1,000 字**；小節（##）**至少 6 個**（含常見問題）
- 內容要專業、具體、有結構：定義、原理、比較、實務建議、注意事項缺一不可
- 每篇至少使用 **1 個表格或 1 個 Callout**；主題適合者（對照、比較、規格）優先使用表格
- 事實陳述以通用鋼筆知識為準：尺寸範圍、品牌歷史、墨水特性等寫「常見/約略」說法，不編造精確數據
- 語言為 zh-Hant 臺灣慣用語（筆蓋、筆舌、墨囊、吸墨器、銥粒、暈墨、刮紙…）
- 每篇最後務必有 `## 常見問題` 小節（3–5 組 Q/A）

## 5. 檢查方式

在專案根目錄執行（PowerShell）：

```
python build.py --check data/articles/<章節id>
```

輸出 `✗` 為錯誤（必須修正），`⚠` 為警告（建議修正）。全部錯誤修正後，再對整個專案跑一次
`python build.py --check`，確認無 `✗` 才回報完成。

## 6. 範本（種子文章）

已完成的示範檔（請模仿其結構與品質）：

- `data/articles/overview/basics/capillary-action.md`
- `data/articles/nib/size/nib-sizes.md`

範本涵蓋：frontmatter 全欄位、表格、Callout（提示/注意/小知識）、FAQ、清單、粗體強調。
